# Instance 0 audit — 2026-11-20

MuMu Disk Cleanup is repaired in the repository and installed on instance 0.
The core installer/upgrader includes the client, daemon, SELinux policy, init
service and checksums. The matching SUSFS package hides the maintenance socket
from ordinary apps. The actual MuMu button reclaimed space; it is not a simulated
success dialog. See [Disk Cleanup evidence](DISK-CLEANUP.md).

The environment retains MuMu's original 4.19.195 kernel. KernelSU ordinary root,
Manager authorization, enforcing startup and module loading are qualified.
The SUSFS engine is the maintained independent LKM with measured MuMu adaptations
and canonical v2.4 protocol additions. It is not a replacement canonical kernel.

## KernelSU investigation

The missing import was **path_umount**. A build-source backport cannot add a
symbol to the already-running vendor Image. The patch uses the available
`ksys_umount` path and removes the inappropriate backport detection. The rejected
Kbuild/sucompat hunks were rebased; upstream already incorporated the kernel-side
`READ_ONCE(*filename_user)` change. MuMu-specific fault-capable pathname reads,
execveat argument handling, late LSM insertion, stack/preemption adaptations,
module pinning and reboot control remain necessary.

The initially linked UAPI-6 build caused released ksud to skip module boot stages
while returning success. The delivered module retains UAPI 5 and the boot script
checks it before startup. This is the material compatibility reason to retain
that API contract. Optional newer symbol/preinit interfaces are not deployed.
All **206 core imports** and **153 SUSFS imports** match the measured symbol set.
The published predecessor had 209 core imports. See [the port analysis](PORTING.md).

## Changes made

The root/mount/map audit fixed 4.19 filename ownership and lookup crashes,
O_PATH identity handling, hardlink/filesystem matching, pre-copy directory and
kstat filtering, map_files listing/lookup/revalidation leaks, mapping rollup,
loop-rule refresh, full-clone kstat flags, overlay views, kallsyms layout,
redirected-FD metadata and IN_OPEN notification. New KSU mounts are tagged before
propagation, tags survive clones, and teardown removes stale mount-ID records.
A whole-filesystem bind no longer hides the original `/data` mount. FD metadata
also derives visible mount IDs directly when the upstream 1,024-entry cache is
full; 1,100 simultaneous mounts reproduce the old leak and pass with 1.2.3.

Disk Cleanup no longer depends on a general root shell in the vendor app. Its
fixed command is served by a dedicated UID-1000 daemon with only CAP_SYS_ADMIN,
NoNewPrivs, a separate SELinux domain and a syscall filter confined to FITRIM on
the pre-opened `/data` descriptor. Normal apps cannot use its protocol or discover
the socket through stat/connect. The original inode modes remain intact.

Installer/maintenance changes include staged payload verification before writes,
idempotent repeat-install checks, a compatible in-place upgrade command, atomic
payload replacement, boot-contract checks, current source/archive hashes,
ABI import validation, atomic downloads and reliable failure reporting. Upgrade
cleanup now retries a read-only remount if host shutdown fails. The obsolete
mandatory fresh-lab/registration gate and duplicate/dead compatibility code were
removed. Target fingerprints, permission checks and data-integrity validation
remain because they prevent real corruption; no agent instruction file is added.

Frida repairs cover API-32 ART layout discovery, deoptimization synchronization,
Java hook teardown, macOS file watching and r2frida's malformed address setup.
No failed trial bridge guard or trial cleanup client was deployed. Ordinary app
traffic, gameplay values, saves and add-on configuration were not modified by
the delivered root changes.

## Remaining gaps and deployment verdict

Ordinary KernelSU operation and the Disk Cleanup repair are qualified for this
exact MuMu profile. No unresolved import or enforcing-startup failure remains in
the delivered core. [The SUSFS matrix](SELINUX-SUSFS.md) distinguishes canonical
specification, independent LKM behavior, boot defaults and controlled observations.

Canonical 4.19 v1.5.5 is the real historical kernel branch. Sidex's GitHub module
is its configuration/client layer, not an alternative kernel repository. The
current 5.10 v2.4 implementation is the source of the new protocol port. Full
canonical internals still require matching kernel source: in-tree inode/address-
space/task flags, original mount allocation/namespace integration and early boot
hooks cannot be asserted to be identical in an LKM on MuMu's existing Image.
Old TRY_UMOUNT/SUS_SU commands are absent from current dispatch, and AArch32
execution is rejected by this emulator. The newer ARM64 command families are
tested, rather than assumed from their advertised feature bits.

One Frida combination remains broken: **child gating with an active Java bridge**
causes the child to exit 139. The parent survives, ungated execution returns 23,
and native-only gating plus child RPC returns 23. Both runtimes, global
deoptimization and targeted cleanup-guard trials were checked; the failed guards
were discarded. This is not presented as a repaired feature. See
[the reproducible case and upstream evidence](FRIDA.md). `frida-strace`, RustModule
and the Kernel API also lack the required support in this installed environment.

A metamodule supplies module mounting infrastructure. The installed add-ons have
no `system/` replacement payload, so no metamodule is needed or installed here.
Adding one would not establish additional root-hiding coverage by itself.
